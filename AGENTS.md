# Ayureika — быстрый цикл разработки

## Область действия
Правила относятся ко всем изменениям в репозитории. Пользователь утверждает функциональность заранее. Не добавляйте несогласованные функции, зависимости, сервисы и архитектурные решения. Не используйте Docker или Ollama.

## Единый цикл
1. Получите актуальное состояние `main`, проверьте связанные файлы и сформулируйте минимальный объём правок.
2. Внесите исправления в рабочей ветке. Не создавайте отдельный процесс или сервис ради проверки.
3. Выполните проверки по затронутым областям; независимые проверки запускайте параллельно. Не пропускайте обязательные проверки ради скорости.
4. Если проверка не прошла, устраните причину и повторите её. Не скрывайте ошибки и не объявляйте успех без фактического результата.
5. Сделайте коммит и push без дополнительного запроса пользователя; убедитесь, что коммит виден в GitHub.
6. Откройте или обновите PR. Сливайте в `main` без отдельного запроса **только** если все обязательные проверки действительно пройдены, PR допускает merge, нет конфликтов, критических ошибок и угрозы пользовательским данным.
7. Если среда не позволяет проверить Windows, сборку или работу приложения, отметьте это как «не проверено», оставьте PR открытым и сообщите блокирующую причину. Никогда не подменяйте реальный тест чтением кода.

## Минимальные обязательные проверки
- Изменения TypeScript: `npm run build`.
- Изменения Python: проверка синтаксиса изменённых модулей; запуск связанных тестов.
- Изменения BAT/PowerShell/launcher: проверка синтаксиса и сценариев первого, повторного запуска и завершения на Windows.
- Изменения API/SQLite: проверка запуска, запросов, схемы и сохранности данных, включая сценарии сбоя, если затронуты.
- Изменения интерфейса: загрузка страницы без пустого экрана, ошибок JavaScript и отсутствующих ресурсов; проверка адаптивности при изменениях вёрстки.
- Выполняйте существующие тесты CI и не отключайте проверки ради зелёного статуса.

## Защита данных и безопасность
- Не удаляйте и не перезаписывайте пользовательские данные без отдельного согласия.
- Не публикуйте ключи, токены и секреты.
- Не выполняйте опасные миграции без плана восстановления.
- Не создавайте параллельные экземпляры серверов и не завершайте чужие процессы.

## Краткий отчёт
После работы укажите: изменения, реально выполненные проверки и их результат, ссылку на коммит/PR, статус push и merge, оставшиеся препятствия.

**Определение готовности:** код проверен обязательными тестами, опубликован в GitHub и безопасно слит в `main`. Если обязательные проверки недоступны, работа не считается завершённой.
